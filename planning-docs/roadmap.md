# Roadmap and Architecture Notes

This document holds the cross-cutting design principles worth preserving and a catalog of extension ideas for building on the foundation. It is a maintainer-facing reference, not a task tracker — per-implementation guidance lives in each `implementations/<use-case>/README.md`, and participant-facing setup lives in the repository `README.md` files.

## Forecasting taxonomy

Keep three concepts separate:

- **Task / output modality** — what is being predicted. Continuous forecasts predict future values or distributions for a time series (scored with CRPS). Discrete-event forecasts predict the probability of a resolved event and are scored with Brier (binary) or RPS (ordered categorical).
- **Forecasting method** — how the prediction is produced. Numerical forecasters, LLM Processes, and agentic forecasters are method families that apply to either modality.
- **Interaction mode** — how the system is used. Track 1 produces standardized `Prediction` objects for evaluation; Track 2 supports interactive analysis, scenario exploration, monitoring, and Q&A without head-to-head scoring.

Output modality and method family are independent: a time-series task can often be reframed as a discrete-event question, and numerical models can supply features or probabilities that support discrete-event predictors.

## Architecture principles

- `aieng-forecasting` (`aieng.forecasting`) owns stable infrastructure: the data service, cutoff enforcement, evaluation interfaces, prediction payloads, artifact storage, and the reusable agent backbone.
- `aieng.forecasting.methods` owns reusable concrete `Predictor` implementations.
- `implementations/<use-case>/` owns notebooks, task-specific configuration, prompts, and co-located YAML specs (one `specs/` directory per use case).
- Darts is the primary numerical forecasting library.
- Pydantic structured outputs and strong, mypy-clean typing are the default for core interfaces.
- StatCan, FRED, and yfinance are the reference data sources.
- Code, notebooks, specs, and documentation stay aligned; READMEs are part of the product.
- Add methods incrementally — give each reference implementation one strong, runnable baseline before adding a method zoo.

### Agent modes

The agent backbone supports two modes:

- **Track 1 prediction** — configured to emit standardized `Prediction` objects through the evaluation interfaces.
- **Track 2 interactive analysis** — configured for conversation, scenario analysis, evidence gathering, and code execution; its interaction surface differs because it is not scored head-to-head.

A common decomposition is a Gemini-backed **Context Retrieval Agent** for search grounding and source-aware context, and a provider-flexible **Analyst Agent** for reasoning, code execution, and synthesis.

**LLM routing.** Everything routes through the Vector proxy (`proxy.vectorinstitute.ai`) — there are no direct-Gemini sub-agents. Web search is a `search_web` tool backed by the proxy's `{"googleSearch": {}}` extension; code execution runs in an E2B sandbox (provider-independent); the analyst/reasoning model is auto-wrapped in `LiteLlm` pointing at the proxy. LLM Processes use the same proxy seam. See [`vector-llm-proxy.md`](vector-llm-proxy.md) for the full convention and the history of the proxy fixes that made this possible.

## Extension ideas

The repository is a foundation. Each reference implementation's README ends with extensions specific to it; the cross-cutting ones are collected here. Each builds on a complete implementation and has a clear seam in the code.

### Deepen a reference implementation

- **BoC live forecasting** — extend `meeting_schedule.yaml` with the Bank's published future dates and forecast each announcement the day before it happens: genuinely out-of-sample, and the honest test that backtest leakage precludes. Needs annual calendar maintenance.
- **Reports as predictor context** — wire cutoff-filtered documents into the forecast prompt: BoC press releases / Monetary Policy Reports through the LLM-Process `user_prompt_suffix` or the `build_boc_news_config` retrieval seam, and the analogous food-CPI CFPR wiring (extraction already exists; mirror BoC's `PressReleaseStore`). Measure the lift over the quantitative-only baseline.
- **Memory-augmented agent** — an agent that learns from its own resolved prediction errors over time; a generalization of the energy adaptive agent across use cases.

### Agent and analyst depth

Every domain implementation (S&P 500, food, energy, BoC) now ships a **`starter_agent/` module + `99_starter_agent.ipynb`** — a fresh, participant-owned agent template with toggleable proxy news search and E2B code execution, two lightweight tool-usage skills, an interactive (Track 2) cell, and one scored (Track 1) prediction. It is the canonical "build your own" entry point and doubles as a quick end-to-end smoke test of each use case's agent stack. Natural next steps from here: richer E2B code-execution configs, prompt and context-formatting optimization, and deeper Track 2 interactive analyst configurations per use case (see [`../docs/adk-skills-guide.md`](../docs/adk-skills-guide.md) for the skill design rules).

**Repo concierge (shipped).** `getting_started/concierge_agent/` + `99_repo_concierge.ipynb` — a `gemini-3.1-flash-lite-preview` ADK agent that answers bootcamp onboarding questions by searching a committed catalog of public `main` (maintainers rebuild via `scripts/build_concierge_context.py`). Points participants to notebooks, modules, and snippets; complements the domain starter agents.

### Broaden coverage

- **AI stocks / NVDA (in progress, branch `ai-stocks-poc`).** [`implementations/ai_stocks_forecasting/`](../implementations/ai_stocks_forecasting/) transposes the energy/oil stack — the repo's other daily, news-driven, shock-prone series — onto NVDA. Its distinguishing idea is a **discovery loop**: a study-mode agent proposes candidate news patterns, a non-LLM statistics module (`signals.py`) scores each one (precision vs. base rate, lift, held-out validation, Fisher's exact test), and only patterns that clear the gate are written to a master strategy file that the forecaster reads at forecast time. Per-experiment files keep the full research trail — candidates considered and rejections with reasons — so a graduated pattern is auditable and later study sessions do not re-cover the same ground. Currently a scaffold: the energy modules are copied with imports rewired, the NVDA data path is live (`build_nvda_service()` over `YFinanceDailyAdapter`, split-adjusted close, no covariate panel), and the 2025 backtest / 2026 protected-eval specs are written. A shock is defined as a single-day move of at least ±5% in either direction. It was ±7% until the measured model cutoffs made a holdout after January 2025 necessary: the clean Feb–Dec 2025 window holds 13 shock events at ±5% but only 4 at ±7%. The cost is a milder shock, 12% of 2020–2024 sessions. The two numerical baselines (naive last-value and AutoARIMA) have been run over the 2025 backtest and their prediction YAMLs committed as the floor later models must beat. AutoARIMA is fitted on log prices, which makes it a log-return random walk with drift: it beats naive on CRPS at every horizon (8.17 vs 10.67), and its 80% interval errs on the side of too wide (90% coverage, 98% at 21 days, with volatility estimated from all history since 1999), so agents cannot win by widening intervals but have real room to win by tightening them; fitting the baseline on a shorter window is the first thing to try. Diagnosing an earlier raw-price run's -77% forecast exposed a core-library bug: `DartsAutoARIMAPredictor` passed exchange-holiday gaps to statsforecast as `NaN`, and a gap in the second-to-last row flipped the selected model. The predictor now forward-fills gaps for every caller and gains an opt-in `log_transform`; S&P 500 and energy/oil AutoARIMA results committed before the fix predate it and are worth regenerating. The inherited `analysis.py` scoring helpers also computed "80% coverage" from the 20th/80th percentiles (a 60% interval) and ignored `mae_horizon`; both are fixed in the NVDA copy, while the energy/oil copy still has them. The statistics contract (`signals.py`) fixes the graduation criteria — at least 5 matching windows, train lift >= 2, Fisher's exact p < 0.05, a bootstrap CI on lift excluding 1.0, holdout lift >= 1.5 and holdout p < 0.10, all required together. Shock flagging and matched-control sampling are implemented: consecutive-day shocks merge into one event (117 independent events from 151 shock days in 2020–2024), each merged window's news cutoff precedes the episode's first shock, and controls are matched on era and trailing volatility so that headlines which merely track volatility cannot pass for shock predictors. At ±5% the controls' exclusion buffer had to shrink to two sessions; at a week it left only calm sessions eligible and the volatility match collapsed. The train/holdout split is implemented too, by date, with the holdout after the measured cutoff: Feb–Dec 2025, 13 shocks and 13 controls, with 2026 untouched. Controls are drawn from their shock's own period, and a split with fewer than 10 shocks is refused rather than returned. Because the holdout overlaps the 2025 backtest, a pattern-using forecaster's honest score is its protected 2026 result. Pattern scoring is implemented too. Lift is measured against the market shock rate, not the 50% shock share of the matched sample, where lift could never exceed 2 and the gate's MIN_LIFT = 2 would demand a perfect pattern. It comes with an exact one-sided Fisher test and a stratified bootstrap interval. On the real training split a volatility proxy correctly scores lift 1.0 against matched controls, but a spurious 1.9 (p = 0.000008) against random ones, while the earnings calendar scores 4.6 and clears every training criterion. The gate is implemented: `gate_reasons` records why a pattern failed, and undefined values fail rather than slip through. It adds a sixth criterion to the original five, holdout p < 0.10. On a 13-shock holdout, `holdout lift >= 1.5` alone passed a no-effect, possibly memorised, pattern 23–33% of the time in simulation, and the p-value rule cuts that to 1–4%. The cost is power: strong real patterns pass 71% of the time rather than 95%, a trade taken deliberately. Regime labels complete `signals.py`. Expanding percentiles of 21-session realised volatility never use later data, and over NVDA's full history they put 2020–2024 at 23% / 41% / 36% low / normal / high, with the chance that the next session is a shock rising from 5.5% to 18.8%. The cut points, 2.27% / 3.54%, sit close to the hand-set shock-anchor bands. The agent layer is partly retargeted: NVDA analyst prompts, a two-sided ±5% shock task with base rates measured over 2020–2024 (an earnings reaction session is about four times as likely to be a shock as an average one: 50% against 12%), `NvdaStrategyState`, whose patterns re-check the statistical gate on construction and on load, so the master file cannot hold an ungraduated pattern even by hand-editing, measured model cutoffs (`LLM_CUTOFFS.md`), `build_nvda_news_config`, the cutoff-fenced, verifier-audited news-grounded config, and `NvdaPriceForecastPromptBuilder`, whose price history is bounded to five years of weekly averages: NVDA's split-adjusted 1999 prices are cents, and unbounded they filled about two-thirds of a 26K-character payload. The trajectory and shock `AgentPredictor`s are wired under NVDA names (`build_nvda_news_predictor`). The shock payload states that the price history ends one session before `as_of`: closes are released a day late, so the agent never sees the `as_of` session it is forecasting from, and it is told to judge that session from news instead. Shock outcomes are now a derived 0/1 series (`nvda_shock_1d`), so the harness scores binary forecasts with Brier. A ten-origin smoke backtest (five holdout shocks, five volatility-matched controls) runs the news-grounded shock agent against climatology on identical origins, at $0.0104 per origin including the verifier. The agent barely separated shocks from controls (mean P 0.17 against 0.15), sitting on the prompt's volatility anchor, and its traces show one search per origin, because the task-agnostic instruction names no search topics. The shock task spec now names three fenced search topics: the unseen `as_of` session, scheduled next-session catalysts, and unscheduled ones. Re-scored as a same-origin A/B on the only fresh post-cutoff shock origins left outside the gate holdout (16 sessions after a shock, 3 continued), the topics did not help: Brier 0.166 with them, 0.138 without, 0.156 for climatology, at twice the cost. Traces show the topic asking how NVDA moved on the `as_of` session was often wrong, and twice came back as source URLs with no summary. Those passed the leakage verifier as successful results, and one of them was the day after the +18.7% tariff-pause rally. The root cause was the fence: `search_web` admits only information published strictly before the `as_of` date, so asking about the `as_of` session asked for fenced-out news. The shock agent now has an after-close variant that reads the `as_of` close from a price series released at 16:00 on its own session, scored from 20:00 origins through a `SessionDatePredictor` wrapper on every arm. Without the wrapper the 20:00 forecast date matches no outcome and the origin goes unscored. Core `search_web` now retries a verified-clean but empty summary instead of serving bare source URLs. Scored on the same 16 sessions as the second and last iteration on that set, the after-close agent read and cited every `as_of` move correctly but did not discriminate: Brier 0.154 against climatology's 0.156, with mean P 0.227 before continuations and 0.212 before calm-downs. Across three variants, no shock agent has yet separated shocks from calm days better than climatology on post-cutoff data outside the holdout. That set is now closed, and the next measurement is the protected 2026 run. Fresh post-cutoff shock origins outside the holdout are now used up, which limits how many more prompt iterations can be tested honestly before the protected 2026 run.

ETS and Kalman) against a **covariate-aware LLM-Process** across cumulative-return horizons — `SampledTrajectoryLLMPredictor` supports `covariate_series_ids` (exogenous-series prompt blocks), so the "can an LLM use the covariate panel as well as gradient boosting?" comparison is shipped, not deferred.

- Add time-series foundation models or additional numerical methods once an implementation has one strong baseline.
- Explore ForecastBench as a comparison or discussion point.

### Live testing

Record predictions from the reference methods (energy first, given its daily data), persist predictions and reasoning traces, and resolve them as horizons mature — a true prospective Track 1 test, distinct from Track 2 scoring.

**Cutoff-aware evaluation (principle).** LLM/agent forecasters can only be scored honestly on origins *after* the model's training cutoff (~Jan 2025 for Gemini) — earlier origins measure memorised recall, not forecasting, and silently flatter the LLM against the cutoff-safe numerical methods. Energy and S&P 500 both put the LLM-inclusive comparison in a 2025 backtest plus a protected 2026 eval; pre-cutoff windows (e.g. S&P 500's 2020 COVID stress) are kept **numerical-only**. food and BoC still backtest their LLM rows on pre-cutoff windows and should migrate to the same discipline.

`resolution_fn` on `ForecastingTask` is still a placeholder; the derived-event-series approach avoids needing dispatch today, but spread/level-target framings will eventually force it.
